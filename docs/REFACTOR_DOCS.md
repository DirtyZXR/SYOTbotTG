# Рефакторинг системы документов - удаление неиспользуемой функциональности

## Описание проблемы
В админ-панели была кнопка "Сканировать документы" и команда `/load_docs`, которые не нужны в текущей реализации бота.

## Анализ системы документов

### Текущая реализация (активная)
**Динамический файловый браузер** - используется в главном меню:
- Сканирует файловую систему в реальном времени
- Работает с фактической структурой папок
- Не использует базу данных
- Callback handlers: `f_` (папки), `fl_` (файлы), `back_folder` (назад)

### Старая реализация (частично неиспользуемая)
**Статическая система с категориями** - устаревший подход:
- Использует `DOCUMENT_CATEGORIES` из config/categories.py
- Хранит документы в таблице `documents` в БД
- Требует предварительного сканирования и добавления в БД
- Callback handlers: `category_`, `subcategory_`, `document_`

## Удалённая функциональность

### 1. Админ-панель
Убрана кнопка "📚 Сканировать документы"

**Ранее:**
```
1. 👥 Список пользователей
2. 👨‍💼 Управление админами
3. 🔑 Сменить секретный код
4. 📚 Сканировать документы ❌ УБРАНО
5. 📝 Сканировать тесты
6. 🔙 В главное меню
```

**Теперь:**
```
1. 👥 Список пользователей
2. 👨‍💼 Управление админами
3. 🔑 Сменить секретный код
4. 📝 Сканировать тесты
5. 🔙 В главное меню
```

### 2. Команда `/load_docs`
Убрана команда для сканирования документов из папки и добавления в БД.

### 3. Callback handler `admin_load_docs`
Убран обработчик callback для сканирования документов из админ-панели.

## Почему это правильно?

### Преимущества динамического файлового браузера:
✅ **В реальном времени** - изменения в файловой системе сразу видны
✅ **Не требует сканирования** - нет необходимости вызывать команду `/load_docs`
✅ **Простота** - работает с фактической структурой папок
✅ **Меньше кода** - не нужна таблица documents в БД
✅ **Гибкость** - можно добавить новые файлы/папки без изменения кода

### Недостатки старой системы:
❌ **Требует сканирования** - нужно явно вызывать команду для обновления БД
❌ **Дублирование** - данные хранятся и в файловой системе, и в БД
❌ **Сложность** - требует поддержки обеих систем
❌ **Устаревший подход** - жесткая структура категорий в коде

## Что осталось на будущее

Возможна полная очистка от старой системы:
- Удалить `DOCUMENT_CATEGORIES` из config/categories.py
- Удалить функции `get_categories_keyboard()`, `get_subcategories_keyboard()`, `get_documents_keyboard()`
- Удалить handlers `callback_category()`, `callback_subcategory()`, `callback_document()`
- Удалить `DocumentService`, `DocumentRepository`, модель `Document`

**Примечание:** На текущий момент старая система частично используется в callback handlers, поэтому требует осторожного анализа перед полным удалением.
